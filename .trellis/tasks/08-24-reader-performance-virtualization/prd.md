# 修复阅读页大漫画加载卡顿

## Goal

让包含数千页的本地漫画进入阅读页时保持快速响应，并在连续滚动、缩略图跳转、恢复阅读进度和切换章节时保持现有阅读体验。

## Confirmed facts

- `ReaderView` 当前把 `comic.pages` 全量映射为主页面节点和缩略图节点。
- `getReaderData()` 当前一次查询整本漫画的全部页面，并把页面元数据传给客户端。
- 目标漫画《寄生纪元》有 6,170 页，现有阅读页响应约 4.57 MB，浏览器会创建 6,170 个主页面节点和 6,170 个主图元素。
- 主图使用原有的 `pageId` API；数据库中已有页面宽高，可用于估算虚拟列表位置。
- 项目当前使用 Next.js App Router、TypeScript、React 19、Vitest，不应为了本任务随意增加虚拟列表依赖。

## Requirements

1. 阅读页初始请求不得再把整本漫画的完整页面行作为客户端 props；应返回章节清单、总页数、当前阅读页全局位置以及一个有限大小的初始页面窗口。
2. 阅读器主内容必须窗口化，只渲染当前视口附近的有限页面；远离视口的页面只能由占位高度表示，不能创建主图 DOM 或触发图片请求。
3. 缩略图侧栏必须虚拟化，只渲染可视区域和 overscan 范围的缩略图按钮；仍支持点击任意页号跳转。
4. 滚动定位、键盘上下翻页、Home/End、恢复上次阅读页、阅读进度保存、章节分隔条和队列尾部提示必须保持工作。
5. 窗口加载必须按漫画 ID、全局页索引和受控 limit 校验，不能接受或拼接客户端提供的文件系统路径；继续使用 `pageId` 读取图片。
6. 代码应复用现有章节排序和页面宽高字段；不能修改数据库 schema、物理漫画文件、章节排序数据或阅读进度数据模型。
7. 为窗口查询、虚拟布局边界和现有阅读行为增加有针对性的测试；完成后运行 web lint、typecheck、相关 Vitest 和生产构建（若环境允许）。

## Acceptance Criteria

- [ ] 对 6,170 页漫画，初始 HTML/客户端 props 不包含 6,170 条完整页面对象，初始页面请求只返回有限窗口。
- [ ] 阅读页 DOM 中主图元素数量受窗口大小限制，不随整本漫画页数线性增长；缩略图按钮数量同样受可视窗口限制。
- [ ] 首次打开只请求初始窗口附近的主图/缩略图；向下滚动会按窗口请求后续页面，不会一次性请求全书图片。
- [ ] 点击远处缩略图可加载目标窗口并定位到目标页；最后阅读页恢复后仍能正确定位。
- [ ] 章节边界、页码显示、进度保存、键盘快捷键、返回详情和队列下一本功能没有回归。
- [ ] 目录漫画和 zip/cbz 漫画仍通过受控 `pageId` 图片 API 工作；非法漫画 ID、负索引、超大 limit 和越界窗口有稳定的空/错误结果。
- [ ] 相关测试、lint、typecheck 和构建结果明确记录；本任务不覆盖的环境限制明确说明。

## Out of scope

- 不改变图片视觉质量、阅读方向、章节排序、阅读进度语义或数据库表结构。
- 不实现多用户、文件监听、物理文件删除或新的下载能力。
- 不重做整套媒体缓存；只保留现有缩略图缓存与页面图片 API 合同。
